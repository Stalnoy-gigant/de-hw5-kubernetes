## Запуск

Нужны Docker Desktop, kind, kubectl и Python 3. Данные — подготовленный в ДЗ 3 файл `data/vacancies.jsonl`. В репозитории есть сохранённый результат `s3://hh-lake/results/mr_k2.csv` из ДЗ 3 для сверки. Исходный JSONL подаётся отдельно.

Команды выполняются из корня репозитория. Для повторных экспериментов используется пустой одноузловой кластер с именем `de-hw5`.

```bash
kind create cluster --name de-hw5 --image kindest/node:v1.37.0
docker build -t de-hw5-pairs:1 .
docker pull rustfs/rustfs:1.0.1

./run.sh setup /полный/путь/к/vacancies.jsonl
./run.sh memory
./run.sh parallel
./run.sh scheduling
./run.sh quota

python3 src/verify.py
```

`setup` загружает локальные образы в kind и переносит данные в PVC с проверкой SHA-256. В `memory` один и тот же расчёт запускается с тремя пределами памяти. Измерение делается по `memory.peak` cgroup. Число 510,7 MiB из ДЗ 3 относится к пику RSS прогона с одним воркером, который также считал одиночные навыки и тройки.

`parallel` запускает RustFS с четырьмя PVC и внутренним Service, загружает данные через S3 API и запускает Indexed Job. Восемь частей исходного объекта читаются с параллелизмом четыре. Итоговый Job сводит счётчики всех частей, после чего скрипт сравнивает полный CSV с эталоном.

`scheduling` вычисляет заявки из allocatable CPU узла и уже размещённых заявок. Сначала фиксирует `Pending` при нехватке CPU, затем запускает Job высокого приоритета и фиксирует вытеснение. `quota` проверяет отказ в создании второго Pod при превышении 500m в отдельном пространстве имён, затем повторяет запрос после освобождения квоты.

Манифесты, в которых параметры меняются между экспериментами, разворачиваются из шаблонов в `run.sh`. Тестовые реквизиты RustFS передаются через Secret. Доступ к Service внутри кластера. Четыре тома находятся на одном физическом узле.

## Артефакты

| Артефакт | Содержимое |
|---|---|
| `Dockerfile`, `src/pairs.py` | Контейнер с расчётом пар из ДЗ 3 |
| `k8s/`, `run.sh` | Манифесты и порядок проведения экспериментов |
| `logs/00-reference.log` | Источник и SHA-256 эталона |
| `logs/01-setup.log` | Версия кластера, образ, перенос JSONL |
| `logs/02-memory.log` | OOMKilled, замер пика и выбранный предел |
| `logs/03-parallel.log` | Загрузка в S3, журналы восьми частей, reduce, сверка |
| `logs/04-scheduling.log` | Ожидание CPU, вытеснение и запуск ожидавшего Job |
| `logs/05-quota.log` | Отказ API и повторный допуск после освобождения квоты |
| `results/hw3_mr_k2.csv` | Эталонный результат ДЗ 3 |
| `results/pairs.csv`, `results/top10.csv` | Полный результат и первые десять строк |
| `report/report.pdf` | Отчёт и сравнение Kubernetes, YARN и Mesos |

Для пересборки отчёта нужен ReportLab и Arial (macOS) или DejaVu Sans (Linux). Команда `python3 src/build_report.py`.
